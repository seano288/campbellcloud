Throwaway design evidence. Not a player-facing app.

Can learning and rewards vary independently?

Run money or one fixed clock question with Garage or repeatable recruitment. Watch learning facts cross into earnings, purchases and presentation without sharing ownership rules. The pairing buttons are a test bench, not a proposed player selector.

Everything stays in memory, including the fake save store. This file never reads or writes browser storage, imports production modules, requests assets or touches player saves. Close it to discard its state. Open this HTML file directly, with no server or installation.

What this prototype does not prove

Only one question per subject and one five-Bolt Garage Mod are represented. Money progression is a counter and clock progression records outcomes, not a curriculum or a production Mastery implementation. Manual Next and Complete buttons replace the 1,500 ms and 900 ms delays. Teaching, voice, setup, Trophies and celebration art are stubs or absent. Explanation locks and full asynchronous cancellation are not verified here.

Garage explicitly selects practice-money checkout context 2, separately from its main subject. The Legendary cash hint remains visible, but checkout, top-Rung purchases and the rest of the catalogue are not simulated. The new composition must still implement that capability. Typed Preact presentation, voice manifests, static build selection, offline recorded playback and version 1-4 save compatibility need production evidence. The fake store checks key isolation and coherent current synthetic state only.

Source files sit beside this HTML. Tests use the already agreed app-coordination and persistence seams. No production extraction or migration has happened. Human review is still required before accepting the candidate design.
